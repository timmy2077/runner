# 人生事件系统功能实现与调试

实现范围：进入触发范围 → 按事件 ID 展示三卡 → 选择确认 → 结果 → 记录与存档。能力效果暂不执行；没有刷新功能。

关卡已恢复原始 Chunk 预制体方式。请在 Chunk Spawner → Difficulty Levels → Chunks 配置关卡块；详见同目录《原始预制体关卡配置说明.md》。下文 reserveFlatGround / safePadding 的自动平地只对程序地形模式有效，默认预制体模式不会改写你做的地形。

## 1. 最快试用

1. 在 Unity 等待编译完成，打开 `Assets/Scenes/Start.unity`（婴儿），或 `Start 2` 至 `Start 6`。
2. Hierarchy 中找到 `Life Event Points`。每个子物体是一个可独立移动的事件点；六个场景各有三个示例点。
3. 选择子物体，Inspector 最上方用“从事件库选择”下拉框指定事件，也可以直接输入事件 ID。
4. 修改 Transform 设置位置，修改 BoxCollider2D 的 Size / Offset 设置范围。勾选 Scene 视图 Gizmos 可以看见范围和事件 ID。
5. 运行游戏，关闭阶段开场，走进范围。默认落地后才打开三卡。用鼠标或 1/2/3 选卡，再确认；结果页点击“继续前行”。

示例触发器没有运行时进度换算，位置不会随着关卡模式自动变化。示例按短篇路程设置，标准模式也能走到。正式布置时可以随意移动，不需要修改脚本。

## 2. 新增抽卡点

两种方式任选：

- 把 `Assets/Prefabs/Events/LifeEventTrigger.prefab` 拖进场景，然后设置事件 ID。
- Hierarchy 右键或顶栏 `GameObject → Life Journey → 人生事件点`。

也可以创建空物体，添加 `LifeEventTrigger` 组件；它会自动添加 BoxCollider2D 并设置 Is Trigger。首次默认范围为 3 × 4 世界单位。

若当前正式场景没有任何事件点，可使用 `Life Journey → 人生事件 → 在当前场景添加三处示例点`。该操作支持 Undo，不会覆盖已有事件点；需要保存场景。已有点时该菜单不重复添加，手动新增没有这个限制。

事件点建议作为场景根物体或固定 `Life Event Points` 的子物体，不要挂在会被回收的运行时地形块下。

## 3. 触发器 Inspector 参数

| 字段 | 用途 | 常用设置 |
| --- | --- | --- |
| eventId | 事件库中的唯一 ID，大小写敏感 | 婴儿 I01–I04；童年 C01–C04；少年 T01–T04；青年 Y01–Y04；中年 M01–M04；老年 O01–O04 |
| requireGrounded | 进入范围后是否等待玩家落地 | 默认开；需要空中事件时关闭 |
| reserveFlatGround | 分段生成时为范围附近保留平地 | 默认开，避免事件点落在随机坑洞里 |
| safePadding | 范围左右额外平地距离 | 默认 3 米；地形按整段保留，实际可能更多 |
| gizmoColor | Scene 可视范围颜色 | 只影响调试显示 |
| BoxCollider2D Size / Offset | 真正的触发范围 | 注意覆盖玩家实际跑过的高度 |
| Transform Position | 抽卡点实际位置 | 世界坐标，不根据模式重新定位 |

运行时识别 `PlayerController` 所在玩家及其子碰撞体，不依赖随意填写的标签。普通物体进入不会触发。触发器只接受当前旅程阶段所属事件；跨阶段真实布置会有警告，跨阶段查看请用预览。

保留平地只在生成分段时生效。播放期间移动范围到已经生成的地形，旧地形不会被立即重建；重启播放或等进入尚未生成的路段再验证。关闭保留平地后需自行保证路线安全。

事件范围可以覆盖心魔场地，但不会屏蔽、取消或重置心魔攻击。恢复游戏后原攻击继续，正式关卡建议把事件放在战前或战后。

## 4. 修改事件与卡牌

打开 `Assets/Resources/LifeEventSettings.asset`，或使用 `Life Journey → 人生事件 → 打开事件配置`。

展开 Events，每个事件包含：

| 字段 | 说明 |
| --- | --- |
| eventId | 全库唯一，发布后尽量保持不变；改名需要同步更新场景触发器 |
| stage | 所属阶段；必须与真实触发场景匹配 |
| title | 短标题 |
| prompt | 三卡上方的一句事件正文 |
| options | 必须恰好三项，顺序就是卡牌 1/2/3 |
| optionId | 全库唯一的稳定选项 ID，建议 `事件ID_A/B/C` |
| answer | 玩家对事件的回答，例如“不结婚” |
| traitName | 获得经历的名称，例如“自定人生” |
| plannedEffect | 后续预期能力说明，当前只展示和记录，不解析、不执行 |
| resultText | 确认后的反馈文字；空时使用通用结果 |
| narrativeFlag | 后续叙事扩展标记，当前仅保存 |

新增事件：增加 Events 数组元素，填写唯一 ID、阶段、标题、正文和三个选项，再在场景点填写该 ID。复制现有事件后必须修改事件和三个选项的 ID。

可以直接使用现有 24 个事件及 72 张回答卡，也可以全部改写文案。卡面不支持富文本代码，输入的文本按普通中文显示。

修改正在显示的事件不会改变当前三卡，因为打开时已保存快照。想看新文案，关闭预览后重新预览；真实事件已经选过时，请用预览或从菜单开始新人生。不要为反复测试随意改动已经发布的事件 ID。

## 5. 全局可调参数

同一资产下的界面与调试参数：

| 字段 | 作用 |
| --- | --- |
| resumeCountdownSeconds | 结果页继续后的恢复倒计时，0–5 秒；调试时可设 0 |
| keyboardShortcuts | 是否启用数字键与 Enter；鼠标操作始终可用 |
| verboseLogging | 输出真实触发和确认的事件、选项 ID |
| cardFontSize | 卡牌正文字号，18–34 |
| backdropOpacity | 事件全屏底色不透明度 |
| fontOverride | 可选中文字体引用；留空使用系统中文字体 |

横屏三卡并排，竖屏三卡纵排。长内容可在卡牌内部滚动。建议正式文案仍保持简短，避免玩家每次选择都需要滚动阅读。

所有设置只有一份自动加载入口 `Resources/LifeEventSettings`。不要在另一个目录新建同名资产后以为运行时会自动选用它。

## 6. 最方便的调试方式

### 6.1 不影响存档的反复预览

1. 进入任一关卡并关闭开场界面。
2. 打开 `Life Journey → 人生事件 → 调试面板`。
3. 输入任意合法 ID，例如 Y02，点击“打开三卡预览”。也可以选择场景触发器，在 Inspector 点击“预览此事件”。
4. 三种回答都可以分别试。预览允许跨阶段，不写 pending、不写选择、不改变能力、不消耗真实触发机会。
5. 点击结果页“结束预览”或调试面板“关闭预览”。原来在暂停中则保持暂停；原来在跑酷则倒计时恢复。

调试面板显示流程状态、最近操作、真实待选 ID 和所有已记录选择。预览有明显标记，不会被误认为正式选择。真实待选未完成时不允许覆盖预览。

### 6.2 验证真正的碰撞触发

运行关卡后选中事件点，点击 Inspector 的“移动玩家进入此点（真实触发并存档）”。这会移动实际玩家，让物理系统真正触发范围，而不是绕过组件直接调用弹窗。

该按钮会产生真实记录。若该 ID 已经选过不会重复打开；要反复测试请选择预览，或通过主菜单“重活一世”明确清空本轮进度。

### 6.3 校验

使用 `Life Journey → 人生事件 → 验证事件库和当前场景` 检查：事件/选项 ID、三选项完整性、阶段匹配、范围是否启用、同场景重复 ID。事件配置资产的“验证事件库”按钮只验证静态内容。

重复 ID 的配置会拒绝查找，不会随便取第一个事件。同一合法事件被多个触发器引用则允许，只警告它们共享一次选择机会。

### 6.4 常见不弹卡原因

- 仍在开场、暂停、死亡、其他选卡或关卡切换状态。
- 该事件已经在本轮确认过，可在调试面板看到记录。
- eventId 拼写、大小写错误或库里重复。
- 事件 Stage 与当前场景不符。
- 触发器没启用、碰撞器关闭、范围没有覆盖玩家，或被物理层碰撞矩阵屏蔽。
- 默认要求落地，但角色进入后一直腾空，或者落地前已离开范围。
- 触发点在短篇终点之外；移动到可达位置，系统不会为了触发器扩展关卡。
- 播放时改动范围后旧地形没有重建。

Console 会对缺失 ID、重复 ID 或阶段不符的点输出一次警告，避免每帧刷屏。verboseLogging 开启后可以观察成功触发与选项提交。

## 7. 存档与流程约束

事件通过可选 `lifeEvents` 字段扩展当前 v1 旅程档，不更换玩家存档键。老档缺少字段时初始化为空记录，主备档都保留兼容。

数据包含：schemaVersion、choices 列表和 pending 快照（序列化字段为 hasPending + pendingSnapshot；显式标记避免 Unity 把空引用反序列化成空事件）。快照包含三张卡的完整内容、选中索引、是否确认、阶段、触发时位置及刚体速度。选择记录包含稳定 ID、回答、经历、预期效果、结果文字和叙事标记。

确认操作在领域层防重复，按钮连点不会多记。确认后结果页退出再回来仍是结果页；未确认退出仍是原三张卡和原选中状态。修改事件库不影响已保存快照与历史。

只有待选/结果恢复使用保存的事件坐标。结果关闭后，普通死亡从既有检查点重试，已完成的事件不会重新出现。事件不新增检查点，不强制出口补选，不限制每阶段最多三次。

待选时世界时间为零，角色速度不会被清空；恢复后接续。默认落地触发可避免空中恢复。菜单返回和读档可能重建未完成心魔，这是现有旅程读档规则；事件本身不发放胜利。

## 8. 代码结构与后续扩展

| 文件 | 职责 |
| --- | --- |
| Runtime/Events/LifeEventSettings.cs | 事件/三选项数据、全局 UI 参数、静态内容校验 |
| Runtime/Events/LifeEventTrigger.cs | 2D 范围、玩家识别、落地条件、Gizmos、平地参数 |
| Runtime/Events/LifeEventSave.cs | pending、选择快照、校验与幂等确认 |
| Runtime/Events/LifeEventDirector.cs | 范围请求仲裁、打开/恢复/提交、预览隔离 |
| Runtime/UI/JourneyEventPanel.cs | 独立 UGUI 三卡和结果页、输入与响应式排版 |
| Editor/LifeEventTools.cs | Inspector 下拉、预览、创建点、事件校验、调试面板 |
| Editor/LifeEventValidation.cs | 独立 Unity 完整验证入口 |
| Tests/LifeEventLogicTests.cs | 不依赖实际场景的选择事务与错误数据验证 |

现有改动：LifeJourneySession 增加 EventChoice/EventResult 状态与恢复入口；LifeCourseGenerator 支持事件附近平地与 pending 坐标恢复；JourneySave 兼容事件扩展；JourneyUI 暂停页和结局页增加选择回看。

后续能力实现建议读取 choices 重建效果，不要把 UI 确认回调作为唯一发奖来源。普通重试、读档、结果页恢复都可能再次显示 UI，而选择只应生效一次。当前代码没有预先绑定伤害、守护或援手逻辑。

## 9. 自动验证

运行现有编译和纯逻辑检查：

```powershell
./Tools/Validate-Journey.ps1
```

它编译运行时代码和编辑器代码，并包含 LifeEventLogicTests 的选项有效性、三种选择、重复回调、阶段不符、NaN 位置和空账本兼容检查。

事件 Unity smoke 必须在独立项目副本中运行，以免与正在使用的编辑器争用工程。保留 Assets、Packages、ProjectSettings 和已解析的 PackageCache，启动：

```text
Unity.exe -batchmode -force-d3d11 -projectPath <独立副本>
  -executeMethod LifeEventValidation.RunSmoke -journeySmoke -logFile <日志>
```

不要加 `-quit`；测试需要进入播放模式，自行退出。测试使用独立 `runner.lifejourney.smoke` 存档命名空间并在结束后清理。该入口会在副本生成示例点和预制体，不应对正使用的主项目运行批处理。

检查范围：24 事件/72 选项、真实碰撞进入、无默认选择、世界冻结、待选与结果页存档恢复、防重复提交、不重复触发、跨阶段预览不写档、死亡重试、六阶段十八次选择、心魔门槛保留、结局与历史存档回读。

验证结果与截图保留在项目根目录 `Logs/LifeEventValidation/`。具体通过结果以日志中的 `LIFE EVENT SMOKE PASSED` 为准；编译通过不等于实际流程通过。
